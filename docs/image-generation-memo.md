# 完成予想図（MVP）実装メモ

## 目的

診断・素材選択・見積もりなどのフローと、ユーザーとの会話で確定した希望を踏まえ、現状写真からリフォーム後の「完成予想図」を生成する。

## 生成ルール

- 現状写真の間取り、窓、ドア、視点、部屋の比率、見えている構造を維持する。
- ユーザーが指定した床、壁紙、設備、色、素材、スタイルだけを変更する。
- 写真にない情報は推測しすぎない。
- 生成内容は会話履歴・診断結果・素材選択・その他の確定事項をコンテキストとして渡す。
- ユーザーとの追加のやり取りで指定内容を更新し、再生成できるようにする。
- MVPでは精細さより確認しやすさを優先し、低画質出力を許容する。
- UI上の表示名は「完成予想図」とする。

## MVP実装範囲

- フロントエンドは保存済みの現状写真のS3キー、確定プロンプト、直近の会話履歴をLambdaへ送る。
- Lambdaは所有権を確認し、OpenAI画像編集API（`gpt-image-1`、低画質）を実行する。
- 生成画像を `generated/{userId}/{sessionId}/{uuid}.png` に保存する。
- DynamoDBに生成画像のメタデータを保存し、署名付きURLを返す。
- 画像生成に失敗した場合は、既存のフォールバック表示を維持する。

## 今回は対象外

- 生成画像の精度評価・画質改善
- 利用回数の最終調整
- 非同期化（キュー・ジョブ管理）
- 参照画像を別S3キーとして画像APIへ渡す処理。必要性を確認後に追加する。
