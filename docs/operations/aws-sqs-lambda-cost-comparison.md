# SQS・Lambda・DLQ コスト比較（初期検討用）

画像生成やPDF生成を非同期化する場合の、通常のSQSキュー、処理Lambda、DLQ（Dead-Letter Queue）の比較です。

## 結論

- DLQは別の専用サービスではなく、追加で作成するSQSキューです。
- そのため、DLQ自体に固定月額が発生するのではなく、メッセージの送受信リクエストと保存量に応じてSQS料金が発生します。
- SQSは月100万リクエストまで無料枠があります。[AWS公式料金](https://aws.amazon.com/sqs/pricing/)
- Lambdaはリクエスト数と実行時間（GB-seconds）で課金され、月100万リクエスト・400,000 GB-secondsの無料枠があります。[AWS公式料金](https://aws.amazon.com/lambda/pricing/)
- 小規模な初期運用では、SQSとDLQの追加料金はほぼ発生しない可能性があります。ただし、Lambdaの実行時間、S3、AI画像生成APIなどは別途確認が必要です。

## サービス別比較

| 項目 | 通常のSQS | Lambda | DLQ |
| --- | --- | --- | --- |
| 主な役割 | 処理待ちメッセージを一時保持 | メッセージを取り出して処理 | 失敗を繰り返したメッセージを隔離・保管 |
| 課金単位 | APIリクエスト数、データ転送 | リクエスト数、実行時間、メモリ量 | SQSと同じ。DLQへの送受信・保持が課金対象 |
| 無料枠 | 月100万リクエスト | 月100万リクエスト + 400,000 GB-seconds | 通常SQSと合算して月100万リクエスト |
| 固定費 | なし | なし | なし（SQSキューとして扱われる） |
| トラフィック増加への効果 | 待ち行列で吸収 | 同時実行数の範囲で自動処理 | 失敗時の再処理・調査を可能にする |
| 注意点 | 空のReceiveもリクエストとして課金 | 長時間・高メモリ処理ほど高くなる | 保持期間を決めないと不要なメッセージが残る |

## 1ジョブあたりのリクエスト例

### 正常終了

```text
受付Lambda → SQS SendMessage       1リクエスト
処理Lambda ← SQS ReceiveMessage     1リクエスト
処理Lambda → SQS DeleteMessage      1リクエスト
                                      合計 3リクエスト前後
```

### 失敗してDLQへ移動

```text
通常キューで処理を複数回リトライ
        ↓ 最大受信回数を超過
DLQへメッセージ移動（SQSリクエストが追加）
        ↓
担当者が確認・再投入、または保存期限で削除
```

したがって、DLQを追加すると「キュー数に対する月額」が増えるのではなく、失敗メッセージを移動・再処理する分のリクエスト数が増えます。

## 簡易試算の考え方

例として、月10万件の画像生成ジョブを処理する場合です。

| 想定 | SQSリクエストの目安 | Lambdaの計算 |
| --- | ---: | --- |
| 正常処理のみ | 約30万リクエスト | `100,000件 × 平均実行秒 × メモリGB` |
| 1%がDLQへ移動 | 約30万件 + 失敗分の移動・再試行 | 通常処理 + リトライ分 |
| 10%が再処理 | 受信・可視性変更・削除が増加 | 成功するまでの実行回数が増加 |

SQSの月100万リクエスト無料枠内であれば、通常キューとDLQのリクエスト料金は基本的に無料枠内に収まります。Lambdaは、実行時間とメモリ量が支配的です。画像生成そのものを外部AI APIやBedrockで行う場合、その利用料がLambdaより大きくなる可能性があります。

## RENOでの推奨

### 初期リリース

- 画像生成・PDF生成用に通常SQSを1本
- 同じ処理用のDLQを1本
- 処理Lambdaは1つ（処理種別はメッセージの`jobType`で分岐）
- DLQの保持期間を7〜14日程度に設定
- DLQのメッセージ数が1件以上になったらCloudWatchアラームで通知

### 将来の高トラフィック時

- 画像生成とPDF生成でキューを分離
- Lambdaの同時実行数をキューごとに制限
- リトライ回数、可視性タイムアウト、DLQ保持期間を調整
- 大きなメッセージ本文はSQSに入れず、S3のキーだけを渡す
- キューの滞留時間を監視して、処理能力を増減する

## 料金上の注意

- SQSは1メッセージでも64KBを超えると複数リクエストとして計上されます。
- 空のReceiveMessageも課金対象になるため、長時間ポーリングの設定を確認します。
- SQSとLambdaを同一リージョンに置く場合、両者間のデータ転送は無料です。
- Lambdaの無料枠はアカウント・リージョン・アーキテクチャなどの条件を確認してください。
- 実際の見積もりは、AWS Pricing Calculatorでリージョン（東京など）、メモリ、実行時間、リトライ率を入力して算出します。
