# 画像診断ワークフロー

## 目的

ユーザーがアップロードした現状写真から、壁紙・床材・建具などの状態を確認し、修繕・交換・素材提案につなげる。

## メインフロー

```text
ヒアリング
  ↓
リフォーム箇所の確認
  ↓
現状写真をアップロード
  ↓
写真をどう使うか選択
  ├─ 状態を診断する
  │    ↓
  │  部位別の診断結果
  │    ↓
  │  素材提案・概算見積もりへ
  │
  └─ 施工後イメージを作る
       ↓
     既存の画像生成フロー
```

## 写真アップロード後の分岐

写真を受け取った直後に、次の選択肢を提示する。

```text
この写真をどうしますか？

[状態を診断する] [施工後イメージを作る]
```

これにより、診断を必要としないユーザーは既存の画像生成フローをそのまま利用できる。

## 診断結果に表示する項目

部位ごとに以下を表示する。

- 部位：壁紙、床材、建具など
- 素材の推定：例）複合フローリング
- 状態：傷、浮き、黄ばみ、色あせ、汚れなど
- 劣化の有無：写真から見て劣化している／明らかな劣化は見られない
- 推奨対応：補修、張替え、交換など
- 次のアクション：素材を探す、概算を見る、施工後イメージを作る

## ダミー診断結果の例

```json
{
  "room": "リビング",
  "areas": [
    {
      "name": "壁紙",
      "issue": "継ぎ目の浮き・黄ばみ",
      "degraded": true,
      "recommendation": "張替え"
    },
    {
      "name": "床材",
      "material": "複合フローリング（推定）",
      "issue": "細かな擦り傷",
      "degraded": false,
      "recommendation": "経過観察または部分補修"
    }
  ]
}
```

## モックで確認する状態

- 写真未選択
- 写真選択後のプレビュー
- 解析中
- 診断結果
- 別の写真を診断
- 診断結果から素材提案・概算へ遷移
- 写真が不鮮明、対象箇所が写っていない場合の案内

## 今後の実装方針

まずは`index.html`の既存写真アップロード導線へ、診断分岐とダミー結果を合流させる。AI解析APIの接続は後段とし、先にユーザー体験と情報の受け渡しを確認する。

現在のモックは、写真の内容にかかわらず固定の診断結果を表示する。画面上では「デモ」と明示し、実際の画像解析や確定診断と誤認させない。

劣化判定は、具体的な3段階評価ではなく、写真から見ておおむね劣化しているか、明らかな劣化がないかの2段階で扱う。写真だけでは判断できない場合は、劣化の有無を断定せず、現地確認を案内する。
