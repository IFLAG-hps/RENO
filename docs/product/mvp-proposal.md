# RENO リフォーム相談MVP 設計案

### タスク名

写真ベースのリフォーム相談MVP実装

---

### 提案内容

現在のモックをもとに、写真を起点としたリフォーム相談サービスのMVPを実装する。

利用者は、チャット形式で相談内容を入力し、写真をアップロードする。システムは写真・要望をもとに、リフォーム提案、施工事例、概算見積もりを表示する。最終的に、入力内容を引き継いだ状態で担当者への相談受付まで完了できるようにする。

図面の入出力、CAD連携、図面解析は今回のMVPには含めない。

---

### 現状の課題・背景

- リフォーム相談の初期ヒアリングに時間がかかる
- 写真、要望、予算などの情報が複数のやり取りに分散しやすい
- 担当者へ引き継ぐ前に、利用者の検討内容を整理する必要がある
- 現在のモックで確認できている導線を、実サイトとして検証したい
- まずは図面機能を除外し、写真・チャット中心の価値検証を優先する

---

### 費用対効果（定量）

以下は初期検証用の仮置き。実装後に実績値で更新する。

- 1件あたりの初期ヒアリング・情報整理時間を、担当者30分から10分程度へ短縮
- 月100件の相談で、月約33時間の作業削減を想定
- 相談内容の抜け漏れを減らし、担当者が初回連絡時に確認すべき項目を標準化

| 工程 | 内容 | 担当者 | 現状時間 | 削減時間 |
| --- | --- | --- | ---: | ---: |
| 1 | 相談内容の初期ヒアリング | 営業・担当者 | 20分/件 | 10分/件 |
| 2 | 写真・要望・予算の整理 | 営業・担当者 | 10分/件 | 7分/件 |
| 3 | 初回提案に向けた情報確認 | 営業・担当者 | 15分/件 | 5分/件 |
| **合計** |  |  | **45分/件** | **22分/件** |

※ 月100件の場合、22分 × 100件 = 約36.7時間/月の削減見込み。

### 開発技術・方法

- 使用技術：HTML / CSS / JavaScript、AWS Amplify Hosting、API Gateway、AWS Lambda、Amazon S3、Amazon DynamoDB
- 実装形態：フロントエンドはAmplify Hostingで配信。API GatewayからLambdaを呼び出すサーバーレス構成
- データ格納：
  - 写真・生成画像・PDF：Amazon S3
  - 会話セッション・相談内容・概算見積もり：Amazon DynamoDB
  - ログインが必要になった場合：Amazon Cognito
  - 画像生成・PDF生成などの重い処理：SQS＋Lambdaで非同期化（初期は処理時間と費用を見て判断）
- AI連携：AIチャット・画像診断・画像生成は、LambdaからBedrockまたは外部AI APIへ接続可能な構成にする
- 通知：担当者相談受付は、初期はメール通知を想定。CRM連携は後続フェーズとする

### 備考・補足

- 今回のMVPには、図面アップロード、図面解析、CAD連携、図面からの出力生成を含めない
- 現在のモックにあるAI応答は、実装初期ではモックまたは限定的なAPI接続として検証可能
- 担当者相談は、受付内容を保存して通知するところまでをMVP範囲とし、CRMへの自動登録は後続対応とする
- 画像生成・PDF生成は、処理時間と同時実行数を見てSQSによる非同期化を判断する
- 個人情報・写真の保存期間、削除方法、アクセス権限を本実装前に決定する
- 費用対効果の数値は仮説であり、PoCまたは初期運用で実測して更新する
