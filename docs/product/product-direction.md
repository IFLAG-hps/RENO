# プロダクト方針

## 目的

写真と会話を起点に、リフォームの相談から提案、概算、担当者への引き継ぎまでを一つの流れで体験できるモックを作る。

## メインの対象

メインの変更対象は、Amplify Hostingで公開する`index.html`およびReact版フロントエンドです。

```text
公開先：Amplify Hostingの公開URL（環境ごとに設定）
Custom domain: https://reno.taskra.jp/
```

`CNAME`を維持しているため、カスタムドメインを主な公開URLとして利用できます。画面内の素材・ページ参照は、どちらのURLでも動く相対URLを使用します。

`index.html`は、認証・チャット・画像生成など一部の実処理を含むアプリモックです。現時点では完成した本番機能ではなく、業務フローとUIを確認するためのデモとして扱います。

## 現在の実装範囲

| 機能 | 現在の状態 |
|---|---|
| 認証・チャット・画像生成 | 外部処理へ接続済みのモック |
| 画像診断 | 固定のデモ結果を表示 |
| カタログ・素材提案 | ローカルのサンプルデータを表示 |
| 概算費用 | ローカルの簡易計算。工期・補助金は固定の参考表示 |
| 提案書PDF | 会話と生成画像を使ってブラウザ内で生成 |
| CRMへの案件登録・担当者連携 | 画面上の導線のみ。外部送信は未接続 |

未接続の機能については、実際に処理が完了したと誤認させない表現を使用します。

## 追加機能の位置づけ

追加機能は、既存の相談体験から自然につながる形で設計します。

1. 画像診断
2. カタログ・素材提案
3. 概算費用・工期・補助金
4. CRMへの案件登録

この順番は固定の画面遷移ではなく、ユーザーの相談内容に応じて行き来できる関連機能として扱います。

## 進め方

1. 画像診断を既存の写真アップロード導線へ合流させる
2. 画像診断結果から素材提案・概算へつなぐ
3. 相談内容・診断結果・提案内容をCRM登録へ引き継ぐ
4. 早い段階で画面を確認してもらい、要件と導線を修正する
5. 方針が固まってから見た目と動きを仕上げる

## 設計上の注意

- 実際のAI解析が未接続でも、将来のAPI接続を想定した画面構成にする
- 診断結果は、カタログ・見積・CRMで再利用できるデータとして扱う
- 既存の画像生成フローを壊さず、「診断する」か「そのまま生成する」かを選べるようにする
- 画像診断はスキップ可能とし、診断を行わずに素材提案や画像生成へ進める
- 部屋・部位の切り替えは既存の設計・操作方法に準拠する
- 担当者への相談は任意のタイミングで開始でき、その時点の情報をCRMへ引き継ぐ
- AIの診断結果は確定診断ではなく、提案のための参考情報として表示する
