### 本番公開の対象

今回は画面だけを公開するのではなく、動的機能を含む本番用構成として公開する。

- React版メイン画面
- API Gateway + Lambdaによるチャット・診断・相談受付
- DynamoDBへのセッション・相談情報保存
- S3への画像・生成ファイル保存
- Cognitoによる認証基盤
- Amplify Hostingによるフロントエンド配信（内部配信基盤はCloudFront）

バックエンドはGitHub Actionsの `Deploy full MVP` または `Deploy backend only` でデプロイする。フロントエンドはAmplify Hostingのリポジトリ連携でビルド・公開し、発行済みのAPI URLをAmplifyの環境変数へ設定する。

Amplifyのビルド設定はリポジトリ直下の `amplify.yml` に定義する。必要な環境変数は以下のとおり。

- `RENO_API_URL`：API Gatewayの `/v1/agent` エンドポイント
- `RENO_MOCK_CHAT`：`false`
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`

Amplifyでカスタムドメインを設定すれば、DNS・HTTPS証明書・デプロイ反映をAmplify側で管理できる。

本番公開後は、画面表示だけでなく、チャット、画像アップロード、画像診断、相談受付、データ保存まで動作確認する。

## Supabase廃止方針

Supabaseは今後使用しない。現在の実装にはSupabase依存が残っているため、代替機能を実装してから設定・SDK・コードを削除する。

### 現在の依存箇所

- フロントエンドのSupabase JavaScript SDK
- Googleログインとセッション確認
- APIリクエスト時のSupabase用 `apikey` / `Authorization` ヘッダー
- `SUPABASE_URL`、`SUPABASE_ANON_KEY` による公開設定

### 移行先の仮方針

- 認証：Amazon Cognito User Pool
- API認証：CognitoのJWTをAPI Gateway/Lambdaで検証
- ゲスト利用：PIN認証を使わずに利用開始できる方式とする
- フロント設定：`RENO_API_URL`などAWS関連設定のみを使用

認証方式が確定するまでは、Supabaseの設定を削除しない。削除すると、現在のReact版のログイン・セッション・動的API呼び出しが動作しなくなる。

## メール送信機能の扱い

メール送信機能はいったん仮機能として扱い、本番公開の必須要件には含めない。

- 相談内容は現行どおりDynamoDBへ保存する。
- SESの送信元・送信先が未設定の場合はメールを送信しない。
- 本番環境にメール送信設定（`SES_FROM_EMAIL`、`SES_TO_EMAIL`）は当面投入しない。
- 後続フェーズで、送信先・送信内容・失敗時の扱いを決めて正式実装する。

## 詳細整理

### 1. PIN認証を廃止

#### 仮の対応方針

- 初回表示時のPIN入力画面を削除する。
- PIN入力を前提としているボタン、説明文、モーダル、エラーメッセージを整理する。
- ゲストPINの発行・検証・一覧・削除などの管理機能も実装対象から外す。

#### 確認事項

- 利用開始時はPINなしで進める。
- 管理者向けの認証・認可は、PINとは別の方式で管理する。
- 認証や同意確認が必要な機能は、対象機能ごとに別途定義する。

### 2. PC表示への対応

#### 仮の対応方針

- スマートフォン表示を基準にしつつ、PCでは横幅を有効活用する。
- チャット画面、メニュー、画像表示、モーダル、入力エリアがPC幅で崩れないようにする。
- PCではコンテンツの最大幅を設定し、過度に横へ広がらないレイアウトにする。
- 画面幅に応じて、ナビゲーションや補助情報の表示方法を切り替える。

#### 確認事項

- 対応するPC画面幅の目安（例：1280px、1440px）を決めるか。
- タブレット表示も今回の対象に含めるか。
- PCではチャット画面を中央寄せにするか、左右に補助エリアを設けるか。

### 3. メニューの再配置

#### 仮の対応方針

- 右上に分散しているメニューや主要操作を、チャット入力バーの上部にまとめる。
- ユーザーが入力前後に確認・操作しやすい位置に配置する。
- メニュー項目の優先度を整理し、頻繁に使う操作を優先して表示する。
- PC・スマートフォンの両方で、入力操作を妨げない配置にする。

#### 確認事項

- 「右上メニュー表示など」に含める具体的なメニュー項目は何か。
- メニューを常時展開するのか、ボタン押下で開くのか。
- 入力バー上部に配置する対象は、全メニューか、主要メニューだけか。

### 4. PC表示時のQRコード常駐

#### 仮の対応方針

- PC表示時のみ、「スマホで開く」ためのQRコードを画面内に常駐させる。
- QRコードはチャット操作を邪魔しない固定位置に配置する。
- スマートフォン表示時はQRコードを非表示にする。
- QRコードの遷移先は、現在表示しているサービス画面のURLとする。

#### 確認事項

- QRコードは画面右側に固定するか、入力バー上部などに置くか。
- PC表示時に常に表示するか、一定時間後に折りたたむか。
- QRコードの横に「スマホで開く」などの説明を表示するか。
- QRコードの遷移先をトップ画面にするか、現在の画面・セッションを引き継ぐURLにするか。

### 5. LPページの削除

#### 対応内容

- `pages/lp.html`を削除した。
- メイン画面、エージェント画面、収益構造ページからLPへのリンクを削除する。
- エージェント画面の戻る処理はメイン画面へ遷移させる。
