RENO / REQUIREMENTS BRIEF

画像AI診断を
「参考判定」として実装する

写真から見える内装の状態を整理し、素材提案・概算・施工後イメージにつなげる。

今回の確認ポイント
画像AIには実用例がある。ただし、画像だけで経年数や原因を断定する仕組みではない。
上長説明用2026-09-07
01 / POSITIONING

画像から判定できる範囲を限定する

「おおむね劣化している／明らかな劣化は見られない」は、現地調査の結果ではなく、写真から見える状態に基づくAIの参考判定。

画像で扱いやすいもの

  • 壁紙の浮き・剥がれ・黄ばみ
  • 床の擦り傷・へこみ・変色
  • 建具の色あせ・傷
  • シミ・黒ずみなどの外観

画像だけでは断定しないもの

  • 劣化の正確な年数・原因
  • 内部の腐食・漏水
  • 安全性・修繕の緊急度
  • 正確な工事費

02 / EVIDENCE

建物点検では、画像AIの実用例が存在する

既存の実例は、主にコンクリートや外壁の「見える変状」を対象にしている。

撮影スマートフォン・連続写真・ドローンなどで対象を撮影
→
画像解析ひび割れや変状を検出・分類・計測
→
人が確認AI結果を点検者が確認し、最終判断に利用
RENOへの示唆
住宅内装でも「部材」「見える状態」「劣化の有無」を出す設計は可能。ただし、最終的な施工判断は現地確認につなげる。
出典：国土交通省 技術資料・点検支援事例3
03 / RENO FLOW

RENOでは、診断結果を次の体験へつなげる

1. 写真保存S3へ画像本体、DynamoDBへ写真メタ情報
→
2. AI分析LambdaがS3画像をOpenAIへ渡し、診断結果を取得
→
3. 次の提案素材提案・概算・施工後イメージへ連携
画面表示例
対象部材壁紙（クロス）、床材、建具（ドア枠）
状態説明継ぎ目の浮き・黄ばみが見られます
劣化の有無おおむね劣化している / 明らかな劣化は見られない
注意書きAIによる参考判定。現地確認で結果が変わる場合があります。
現在の実装対象：analyze_photo4
04 / OPEN DECISIONS

正式仕様として、ここは相談して決めたい

論点決める内容推奨案
対象範囲診断する部材と最大件数内装3〜5項目から開始
劣化の有無写真から劣化していると見えるか具体的な段階評価は行わず、2段階で参考表示
信頼度confidenceを表示・保存するか内部保存し、低信頼時は注意表示
連携概算・生成の入力に使うか提案の補助情報として利用
最終判断現地確認への誘導必ず参考判定と明記
合意事項
診断は「施工判断」ではなく、「ユーザーが次の相談行動を選ぶための補助情報」として位置付ける。

05 / PROPOSAL

まずは、検証可能な最小仕様で進める

今回のMVP

  • S3上の写真をAIへ渡す
  • 部材・状態・劣化の有無をJSONで取得
  • 画面に参考判定として表示
  • DynamoDBの写真レコードへ保存

後続で拡張

  • 信頼度・再分析履歴
  • 判定基準のチューニング
  • 概算・生成への自動連携
  • 人による確認フロー
次のアクション
合意した位置付けと出力項目で、dev環境に実装を反映し、実画像を使った表示・失敗時・自然言語指定の検証へ進む。
